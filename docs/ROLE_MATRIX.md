# Lost-Found 权限矩阵

## 角色边界

| 能力 | 校园用户 `common` | 审核员 `lostfound_reviewer` | 运营管理员 `lostfound_operator` | 超级管理员 `admin` |
| --- | --- | --- | --- | --- |
| 注册、登录、个人资料 | 是 | 是 | 是 | 是 |
| 发布、编辑、撤回自己的帖子 | 是 | 是 | 是 | 是 |
| 查看已审核公开内容 | 是 | 是 | 是 | 是 |
| 查看和处理与自己有关的认领 | 是 | 是 | 是 | 是 |
| 评论、私信、举报、申诉 | 是 | 是 | 是 | 是 |
| 查看帖子审核队列 | 否 | 是 | 是 | 是 |
| 审核、拒绝、下架帖子 | 否 | 是 | 是 | 是 |
| 查看匹配和认领管理数据 | 否 | 只读 | 是 | 是 |
| 管理分类和地点 | 否 | 否 | 是 | 是 |
| 处理举报、案件、处罚、申诉 | 否 | 否 | 是 | 是 |
| 管理系统角色、菜单和管理员 | 否 | 否 | 否 | 是 |

## 强制规则

1. `common` 只能通过门户接口访问自身数据；帖子、认领、私信和申诉接口必须在服务层再次校验归属。
2. `lostfound_reviewer` 只获得帖子审核和匹配查询权限，不获得用户、角色、菜单管理权限。
3. `lostfound_operator` 获得失物招领业务治理权限，不获得系统角色和管理员账号管理权限。
4. `admin` 是系统最高权限角色，只应分配给受信任的运维人员。
5. 管理员不应通过业务接口读取用户密码、令牌或未脱敏联系方式；私信正文只在必要的治理流程中受控访问。

## 数据权限验收

- 用普通用户登录管理端菜单地址，接口必须返回 `403`，而不是只隐藏前端菜单。
- 用审核员登录，帖子审核接口允许访问，用户/角色/菜单接口必须返回 `403`。
- 用运营管理员登录，举报、案件、处罚和申诉接口允许访问，系统角色接口必须返回 `403`。
- 变更角色后应重新登录或刷新权限缓存，再进行验收。

角色和菜单的幂等初始化脚本为 `backend/sql/lost_found_role_seed.sql`。
如果基础角色脚本已执行，再执行
`backend/sql/lost_found_role_matrix_fix.sql` 补齐运营管理员的分类新增、
修改和删除权限。
